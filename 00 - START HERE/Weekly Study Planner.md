# Weekly Study Planner

## 1. Default weekly template (independent study, outside class)

The template assumes about **18 hours of independent study per week**. Scale it to your real timetable, but keep the *proportions*. Practical subjects (Python, Cyber Security labs) get more hands-on time because skill comes from doing. This is a pedagogical choice, **not** a reading of your LTP values (see [[Module Register]]).

| Block | Mon | Tue | Wed | Thu | Fri | Sat | Sun |
|---|---|---|---|---|---|---|---|
| **A (60–90 min)** | Python lesson | Discrete Math lesson | Python lesson / exercises | Cyber Security lesson | Software Design lesson | **Lab or project milestone** (2–3 h) | **Weekly review** (60 min) |
| **B (45–60 min)** | Project Mgmt lesson | Discrete Math problem set | Final Year Project task | Cyber Security exercises | PM calculations practice | | Plan next week (15 min) |
| **C (20 min)** | Reviews due ([[Review Schedule]]) | Reviews due | Reviews due | Reviews due | Reviews due | | |

Approximate hours per module per week: Python 4 · Cyber Security 3.5 (including labs) · Discrete Math 3 · Project Mgmt 2.5 · Software Design 2.5 · Final Year Project 2.5.

## 2. Rules that make the plan work

1. **Retrieval first.** Every block starts with 3 minutes of recall: "What did I learn last time in this module?"
2. **Exercises are not optional.** A lesson counts as done only when its L1–L3 practice is attempted ([[Mastery Rubric]]).
3. **Interleave.** Never do more than 90 minutes on one module in a row. Mixing subjects improves long-term retention.
4. **Protect Saturday practicals.** Labs and projects turn knowledge into evidence of competence (level 5).
5. **The Sunday review** is non-negotiable: blank-page recall of the week, update [[Progress Tracker]], move unfinished items in [[Next Actions]].
