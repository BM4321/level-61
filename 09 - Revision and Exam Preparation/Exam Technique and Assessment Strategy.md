# Exam Technique and Assessment Strategy

> [!warning] Formats weren't supplied
> No official exam formats, durations, mark schemes or assessment weightings were supplied for these modules ([[Syllabus Verification Log]]). The mocks in this folder use **designed** formats. Find out the real ones from your lecturers and handbooks, and adjust your preparation to them.

## 1. Before the exam period
1. **Get the facts:** the format of each paper (duration, sections, choice of questions), what's allowed (calculators, formula sheets), and the coursework weighting.
2. **Map the readiness rule** ([[Mastery Rubric]]): every core topic at level ≥ 3, and ≥ 70% at level ≥ 4.
3. **Schedule mocks** at least 2 weeks before each exam, so there's time to act on the results.
4. **Prioritise** from the [[Weak Area Tracker]] and the curriculum maps: topics that other topics depend on come first.

## 2. Time allocation
Minutes per mark = (paper length − reading and checking time) ÷ total marks. For a designed 3-hour, 100-mark paper with 10 minutes for reading and 10 for checking: 160 ÷ 100 = **1.6 minutes per mark**, so a 15-mark question gets about 24 minutes. When the time is up, move on, and leave space to come back.

## 3. Command words
| Word | What it asks | Typical mistake |
|---|---|---|
| Define / state | A precise statement; no explanation needed | Writing an essay |
| Describe | What it is or does | Explaining why (not asked) |
| Explain | How or why, with reasons | Describing only |
| Compare / contrast | Similarities **and** differences, point by point | Two separate descriptions |
| Evaluate / assess / justify | A judgement, with evidence for and against | No conclusion |
| Calculate / compute | Working and an answer with units | Only the answer |
| Prove / show that | A logically complete argument | An example instead of a proof |
| Design | A solution that meets stated requirements, with justification | Generic designs not tied to the scenario |
| Trace | Step-by-step state changes (e.g. variables per iteration) | Skipping steps |

## 4. Answer structures by module
| Module | Typical question type | Structure that earns marks |
|---|---|---|
| PY | Write or fix code; trace output; explain an error | Clarify the input/output; write the function; show a test call; name the edge cases |
| DM | Prove; compute; translate | State what's given and what's to prove; justify each step by a law or rule; box the result |
| CS | Explain a control; analyse a scenario; compute risk | Threat → vulnerability → control → residual risk; tie every control to the scenario |
| PM | CPM/PERT/EVM calculations; plans; scenario judgement | Table of working (ES, EF, LS, LF; or PV, EV, AC); interpret the numbers; recommend an action |
| SD | Requirements; UML; design principles; testing | Draw the model with correct notation; explain one design decision and its trade-off |
| FYP | Proposal; defence questions | Problem → gap → method → plan → ethics; answer, support with evidence, acknowledge limitations ([[FYP-12 Presentation, Defense and Working with Supervisor Feedback]]) |

## 5. During the exam
1. Read the whole paper (5–10 minutes). Mark the questions you can do best.
2. Start with a strong question, to build momentum, not necessarily with question 1.
3. Underline command words and constraints ("using CPM", "in Python", "for this scenario").
4. Show working: method marks often survive a wrong final answer.
5. State any assumption you make ("assuming the durations are in weeks…").
6. Leave 10 minutes to check: units, signs, off-by-one errors, unanswered parts.

## 6. After a mock
1. Mark it with the marking guide, honestly, within 24 hours.
2. Log every lost mark in [[Mistake Log]], with its cause.
3. Any section below 50% → [[Weak Area Tracker]].
4. Redo the lost-mark questions after 3 days, closed book.

## 7. Integrity
Mocks here are **designed practice papers**, not past papers. Use only materials your institution permits in an exam, and follow its rules on collaboration and AI tools in coursework ([[FYP-10 Research Ethics, Privacy, Academic Integrity and Citation]]).
